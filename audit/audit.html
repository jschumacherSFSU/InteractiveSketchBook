Interface Audit - Menu

This is the interface audit page.

Visibility of System Status

The page clearly states it is a menu screen. The buttons clarify where to interact on the page. It could clearer between going to an individual condition or going through the entire sequence.

Affordance & Signifiers

On the menu page, there are buttons to open a condition page, or a button to go through the sequence. The actions are labeled on each button. All the buttons are labeled. There are not any unclear interactive features.

Navigation & Mapping

There is a splash page that opens to the main menu. From there the user can navigate to an individual condition pages. The hierarchy seems clear to me, but it might be clearer if the Begin Exam button were first and then the individual options. The hesitation could occur while trying to understand the options available to the user.

Constraints & Assumptions

The page assumes the user knows how to use basic software/web page controls like buttons. There is nothing hidden on the screen. The user doesn't know what the "exam" will look like. There are no restrictions outside of the limited buttons.

Heuristic Violations

User Control & Freedom: There is no way to go back to the main menu once you click on a condition. The user can only go forward through the sequence. This could be fixed by adding a "back to menu" button on each condition page. Identify two Nielsen heuristics your page violates. Name the heuristic. Describe the violation. Identify where it occurs.
